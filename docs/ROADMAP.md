## 2. التفاصيل المرحلية

### المرحلة 1: النواة والأساسات — Sprint 1 (أسبوعان)

> **الهدف:** بناء البنية التحتية الكاملة للتطبيق — المعمارية، قاعدة البيانات، الثيم، ومحرك التبديل.

| # | المهمة | الأولوية | المخرج |
|:---:|:---|:---:|:---|
| 1.1 | تهيئة مشروع Flutter وإعداد بنية المجلدات (Feature-First) | 🔴 حرجة | مشروع يعمل بدون أخطاء |
| 1.2 | إعداد Riverpod v2 مع الأنماط المعتمدة (Notifier / AsyncNotifier) | 🔴 حرجة | Providers أساسية تعمل |
| 1.3 | بناء قاعدة بيانات Drift (جميع الجداول + التغذية المسبقة للأغذية) | 🔴 حرجة | 6 جداول + 200+ صنف غذائي |
| 1.4 | بناء نظام الثيم العربي (ألوان مهدئة + Tajawal/Cairo + RTL) | 🟡 عالية | ThemeData كامل |
| 1.5 | برمجة محرك التبديل الديناميكي (AppModeNotifier + 4 أوضاع) | 🔴 حرجة | التبديل يعمل بسلاسة |
| 1.6 | بناء شاشة الإقرار الطبي الإلزامي (غير قابلة للتخطي) | 🔴 حرجة | Disclaimer يُحفظ محليًا |
| 1.7 | شاشات البداية (Onboarding) لإدخال البيانات الأولية (LMP، طول الدورة) | 🟡 عالية | بيانات كافية لبدء الحسابات |

**معيار القبول:** `flutter analyze` بدون أخطاء + `flutter test` ناجح للحسابات الأساسية.

### المرحلة 2: أدوات الحمل والطوارئ — Sprint 2 (أسبوعان)

> **الهدف:** بناء الأدوات الطبية الحيوية — عدّاد الركلات، مؤقت الانقباضات، التوجيه الجغرافي، ودليل الأغذية.

| # | المهمة | الأولوية | المخرج |
|:---:|:---|:---:|:---|
| 2.1 | شاشات تطور الجنين أسبوعًا بأسبوع (40 أسبوعًا) | 🟡 عالية | بطاقات مقارنة بالفواكه + نصائح |
| 2.2 | عدّاد ركلات الجنين (KickCounterScreen) | 🔴 حرجة | تسجيل + مؤقت + تنبيه خمول |
| 2.3 | مؤقت الانقباضات مع خوارزمية 5-1-1 (ContractionTimerScreen) | 🔴 حرجة | تنبيه أحمر + صوتي + زر مستشفى |
| 2.4 | خدمة التوجيه الجغرافي (GeoRoutingService) | 🟡 عالية | 3 أنواع مرافق + fallback للمتصفح |
| 2.5 | دليل الأغذية التفاعلي مع بحث محلي فوري | 🟡 عالية | بحث < 100ms + تصفية بمستوى الأمان |
| 2.6 | ركن التطمين الجلدي (كارت أسبوعي من الأسبوع 14) | 🟢 متوسطة | بطاقة توعوية عن تصبغات الحمل |
| 2.7 | وضع متابعة الدورة الشهرية (تقويم + أعراض + تنبؤ) | 🟡 عالية | تقويم ملون + تنبؤ بالدورة القادمة |
| 2.8 | وضع التخطيط للحمل (نافذة الخصوبة + BBT) | 🟡 عالية | عد تنازلي + رسم بياني |

**معيار القبول:** جميع الحسابات الطبية مختبرة + المؤقتات لا تسبب Memory Leak + لا إعلانات في الشاشات المحظورة.

## 3. قوائم التحقق

### ✅ قبل كل Commit

```bash
# 1. توليد الأكواد
dart run build_runner build --delete-conflicting-outputs

# 2. فحص استاتيكي
flutter analyze

# 3. تشغيل الاختبارات
flutter test
```

### ✅ قبل كل Sprint Review

- [ ] جميع الاختبارات ناجحة (`flutter test` = 0 failures)
- [ ] لا تحذيرات من `flutter analyze`
- [ ] المؤقتات لا تسبب Memory Leak (فحص بـ DevTools)
- [ ] الواجهات تدعم RTL بشكل صحيح
- [ ] الألوان مهدئة ومريحة للعين

- [ ] تم تعطيل إعلانات الاختبار واستبدالها بوحدات AdMob الإنتاجية
- [ ] تم التأكد من عدم وجود أي إعلان في الشاشات الأربع المحظورة (Kick, Contraction, Emergency, EPDS)
- [ ] تم فحص حسابات EDD والتبويض ومطابقتها لأمثلة طبية معروفة
- [ ] تم اختبار خوارزمية 5-1-1 بسيناريوهات واقعية متعددة
- [ ] التطبيق يعمل بنسبة 100% بدون اتصال بالإنترنت
- [ ] فحص التشفير: النسخة الاحتياطية مشفرة فعلًا ويمكن فك تشفيرها بنجاح
- [ ] الإقرار الطبي يظهر إلزاميًا ولا يمكن تخطيه
- [ ] زر "مسح جميع بياناتي" يحذف كل شيء فعلًا
- [ ] سياسة الخصوصية منشورة على رابط عام يعمل
- [ ] نموذج التصريح الصحي مُعبأ في Google Play Console
- [ ] اختبار على 3 أجهزة بدقات شاشة مختلفة على الأقل
- [ ] لا يوجد `// TODO` أو كود مبتور في المنطق الحسابي أو الاستعلامات
